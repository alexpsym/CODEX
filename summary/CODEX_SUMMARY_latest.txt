1. FX Weekend — Render is the sole execution authority
- Removed FX Weekend from every local automatic-start/default-required path, including run_local_master_control.bat, Render local-profile defaults, and the packaged worker helper. Explicit local wildcard/autostart values are filtered so they cannot silently re-enable the executor.
- Kept the local dashboard entry as "FX Weekend (Render)". It opens the configured Render application URL and reports a clear configuration error when no Render base URL is available; it never opens or mutates the local settings page.
- Render owns and supervises exactly one enabled FX Weekend child, restarts unexpected exits, publishes heartbeat/running information, and treats a dead or unusable enabled executor as a readiness failure.
- Extended shared/oanda_api.py with a public account-mode configuration resolver used by the executor. Demo is isolated to practice credentials/URL; Live follows the repository's live/generic credential conventions and live URL. Each selected account is processed and reported independently.
- Migrated scheduling to Brisbane HH:MM cutoffs while retaining legacy hour keys and the established 05:00 New York-DST / 06:00 standard-time defaults.
- Durable settings now include selected account modes and retry controls. enabled=false is respected and is never overwritten at startup.
- Reworked the closure loop to continue polling throughout the closure window, catch positions opened after an earlier flat result, retry transient failures with bounded backoff, preserve per-account/per-position HTTP results, and avoid a one-week completion latch.
- Success requires a post-close OANDA re-fetch proving the selected account flat. Credential, API, partial-close, retry-pending, missed-window, and market-closed outcomes remain explicit failures rather than manufactured success.
- Settings and status participate in the authoritative state backup/restore flow. The page exposes enabled state, selected OANDA accounts, Brisbane cutoff/next cutoff, DST regime, heartbeat, attempt and verified-flat timestamps, open counts, and sanitized errors.
- Secrets and full account identifiers are redacted from status/log output.

2. Watchlist deletion durability
- Watchlist POST now normalizes the complete proposed sequence, persists it synchronously to the effective durable source, round-trips that source, and confirms success only when the complete normalized sequence matches exactly.
- A stale remote superset can no longer pass verification, and an empty list is a valid verified result.
- Responses expose durable_verified, verified_at, verified_items, effective_state_source, pending, and error.
- Failed durability checks restore/reload the last authoritative watchlist instead of leaving an optimistic deletion visible.
- The dashboard no longer requires a non-empty verified list and does not announce removal until the item is proven absent.

3. TradingView session markers
- Sydney, Tokyo, London, and New York session events are suppressed when each event timestamp lands on a Brisbane Saturday or Sunday; weekday DST-aware timestamps and the <=30-minute visibility rule remain intact.
- Funding and Options Expiry behavior is unchanged.
- Each session event now draws two aligned dotted segments with a candle/wick clearance gap derived from max(recent 80-bar range * 0.03, syminfo.mintick * 20).
- Open/close labels remain centered at the exact event timestamp and sit beyond the applicable line endpoint with additional clearance.
- Cleanup accounts for two line objects per event and removes hidden/expired objects within TradingView limits.

- Added high-DPI responsive canvas rendering, grid/axes/readable limited date ticks, formatted balances, latest marker, title/current equity/currency/point count, saved selection, automatic account redraw, and explicit loading/empty/error states.
- Existing workbook/import/resync/drop-zone/monthly P&L/demo-adjustment/status controls retain their behavior.
