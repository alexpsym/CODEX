CODEX COMPLETION SUMMARY
Brief: Simplify the TradingView range breakout-pullback chart and restore fresh opposite-direction range detection after an active setup or trade.
Recorded: 2026-08-27 (Australia/Brisbane)

CHANGES

- Updated only the canonical pinescripts/range_breakout_pullback_strategy.pine implementation. No duplicate or replacement strategy was created.
- Blue support/resistance zones now default hidden. Breakout, extension, pullback, depth, state-background and custom entry annotations were removed from the normal chart.
- TradingView's native execution markers are now the sole entry/exit source, with compact LONG, SHORT and EXIT comments. The default custom display consists of frozen teal take-profit lines, each bounded by its actual entry and exit bars. The active stop remains available through a separate setting that defaults off, and FX Weekend shading is preserved.
- Added one opt-in Show setup diagnostics control. It restores structural zones and exposes compact stage, gate, reset, range, ATR, session, entry-request and pullback-depth values in TradingView's Data Window without adding candle-label clutter.
- The first code gate blocking the later opposite-direction setup was range observation: confirmed pivots were accepted only while setupStage was 0, the strategy was flat and no order awaited a fill. Pivots confirmed during the preceding bearish setup/trade were permanently missed, so a fresh pre-breakout range and resistance could be absent when the bullish impulse arrived.
- Range candidates now collect on every completed, non-blackout bar, including during an active setup or position. Breakout arming remains restricted to a confirmed range, stage 0, a flat strategy and no live/pending trade risk. This correction is direction-neutral, uses only already-confirmed pivots and never backdates a breakout.
- Preserved all pullback-depth modes, Balanced and other resumption modes, full adaptive-ATR warmup, fixed/adaptive ATR stops, immediate symmetric tick-relative brackets, frozen default 2R targets, one-position behavior, FX Weekend rules, process_orders_on_close=true and the absence of calc_on_order_fills.
