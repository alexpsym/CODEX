Target recommendation analytics update:
- Replaced target recommendation logic based on winner-versus-loser average target distance.
- Target recommendations now come from eligible positive winning R-multiple frequency distributions.
- Eligible target analysis requires genuine non-test winning trades with trustworthy original entry, stop, target, side, and exit data.
- Realized winning R is recalculated from original risk distance instead of trusting a moved-stop or stored R multiple.
- Original planned target R is compared using the median planned target R for the same scope.
- Freedman-Diaconis bin width is snapped deterministically to 0.25R, 0.5R, or 1.0R.
- The modal R bucket becomes the recommended target; tied modal buckets choose the lower R target.
- Recommendation cells now include both direction and numeric recommendation, for example: Reduce target - Recommended: 3.0R (current median: 4.0R).
- Insufficient target data now reports: Insufficient eligible wins - recommended target unavailable.
- JavaScript target recommendation fallback no longer recreates target advice from average winner/loss target distances.
- Trade Log recommendation columns remain removed from the active schema; SYMBOLS and STATS1 receive the target recommendation strings.
