Marker-overwrite root cause:
- `/api/local-shutdown` and `/api/local-exit` already wrote detailed atomic normal-exit markers before SIGTERM.
- The batch worker later called `:write_normal_exit_marker` after Uvicorn returned and unconditionally overwrote that API marker with `batch_exit_request`.
- Controlled exits were still detected, but the wrapper lost whether the shutdown was an Exit-button shutdown, launcher replacement, or another controlled local shutdown.

Marker-overwrite fix:
- `run_local_master_control.bat::write_normal_exit_marker` now calls `tools/windows_launchers/write_local_master_normal_exit_marker.ps1`.
- The helper preserves an existing valid marker unchanged when it has a recognized reason or requesting action, including `exit_button`, `launcher_preflight`, `local_exit`, and `local_shutdown`.
- The helper writes the `batch_exit_request` marker only as a fallback when no marker exists or when the existing marker is empty/corrupt/unrecognized.
- Fallback writes remain atomic through temp-file plus move.
- Corrupt marker evidence is copied to a `.invalid.<timestamp>` file where practical, and the worker log receives a visible diagnostic.
- `local_master_worker_console.bat` continues to consume and remove the marker only after printing the controlled-exit classification.

Latest-generation detection root cause:
- `stream_local_master_worker.ps1` previously searched the entire worker log for any `uvicorn exited with` line.
- A previous generation's exit line, such as generation 1 `uvicorn exited with -1`, could incorrectly satisfy evidence for a later generation that disappeared without its own clean Uvicorn exit line.

Latest-generation detection fix:
- `stream_local_master_worker.ps1` now parses worker-log lines in order and keeps evidence for the latest Uvicorn generation only.
- It recognizes `starting uvicorn`, `uvicorn restart generation N`, and `uvicorn exited with ...`.
- Final evidence now reports worker PID, latest Uvicorn generation, Uvicorn PID as `unknown` when not obtainable, latest-generation startup state, latest-generation exit state, latest-generation exit code, worker exit code, runtime seconds, last successful health timestamp, last successful autostart timestamp, and normal-marker state.
- Earlier generation exits no longer hide a later process disappearance.
- If the latest generation has no exit line and no normal marker, the streamer reports that the process disappeared before clean Uvicorn exit logging and classifies it as external/forced termination unless stronger evidence appears.
- If the latest generation has an exit line, the streamer reports that generation's actual exit code.
