Recommendation-filter root cause:
- The previous target analysis path had grown into a monetary-accounting audit for FX trades.
- It required opening conversion, original monetary risk, OANDA transaction provenance, commission/swap provenance, and related metadata before accepting otherwise valid FX winners.
- Those strict filters blocked the Trading Journal's recorded chart-distance data and left Stats 1 FX target output at `No eligible winning trades`.
- The active target path now uses the recorded Trade Log data for chart-distance analysis: positive recorded `R-Multiple` first, then captured price R from entry/exit/original stop distance.
- Monetary-risk/provenance helpers remain out of the active recommendation path and no service/API wrapper routes back through them.

Worker-exit root cause:
- `/api/local-shutdown` and `/api/local-exit` previously wrote the exit-request marker before SIGTERM, but the normal-exit marker was only written later by the batch loop after Uvicorn returned.
- If the process tree disappeared before that batch branch ran, the visible wrapper could classify a controlled runtime shutdown as a worker failure.
- The streamer also stopped rechecking readiness after the first healthy startup, so post-Uvicorn-restart health/autostart recovery was not visibly validated.
- `fxweekend-clone` was configured in `AUTOSTART_SCRIPTS` but could disappear from resolved autostarts without a visible `/scripts` reason.

Launcher and worker files/functions changed:
- `render/master_service.py`
  - Added `fxweekend-clone` to local allowed apps.
  - Records unavailable configured autostart targets and exposes them in `/scripts`.
  - Writes local exit and normal-exit markers atomically before scheduling SIGTERM.
  - Marker payload includes reason, timestamp, server PID, and requesting action.
- `run_local_master_control.bat`
  - Logs Uvicorn restart generation.
  - Writes the post-Uvicorn normal marker atomically as a fallback.
- `tools/windows_launchers/local_master_worker_console.bat`
  - Distinguishes startup failure, unexpected runtime exit, controlled Exit-button shutdown, controlled replacement, and local shutdown.
  - Uses the normal marker even when the worker process is gone before the batch branch runs.
  - Avoids printing startup-error wording after `Application startup complete`.
- `tools/windows_launchers/stream_local_master_worker.ps1`
  - Continues health/autostart supervision for the worker lifetime.
  - Resets dashboard/scanner readiness after restart detection.
  - Revalidates configured targets: `bybit_monitor`, `oanda_monitor`, and `fxweekend-clone`.
  - Logs restart detected, waiting for recovery, dashboard recovered, autostart recovered/lost, final worker PID/exit evidence, last health timestamp, last autostart timestamp, and normal-marker status.
- `oanda_monitor/oanda_forex_monitor.py`
  - Timeout/retry logging now includes exception class, useful fallback message, account/mode, endpoint, since window, attempt number, and recovery after success.
- `.gitignore` and `PATCH_DESKTOP_PUSH.bat`
  - Added `fxweekend-clone/*.log` so generated FX Weekend runtime logs cannot be committed by the automatic push workflow.
