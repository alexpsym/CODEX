Alert expiry/email, trade numbering/chart folders, funding totals/commission, and ZORAUSDT repair

Root causes and implementation

- Alert expiry did not exist end to end: the UI omitted it and neither monitor enforced it. The Alerts form now defaults to No expiry, converts browser-local date/time to UTC ISO-8601 expires_at, preserves it during edit/save/reload/backup/restore, displays No expiry/expiry/Expired, rejects malformed or past values, prevents re-enabling an expired alert, and excludes expired alerts from evaluation, re-arming, Telegram, and email while keeping them visible. Legacy alerts without expires_at remain non-expiring; fixed-price removal after firing is unchanged.
- Alerts previously had Telegram delivery only. Added the shared standard-library shared/alert_email.py SMTP transport, independent Telegram/email attempts for Bybit and OANDA custom price/move alerts and existing percentage-move alerts, per-channel readiness/test results, and backward-compatible /push-test behavior. Email messages include source, symbol, type, condition, current value, custom message when present, and UTC trigger time. No address, credential, or secret is committed or logged.
- Email configuration required when delivery is enabled: ALERT_EMAIL_ENABLED=true, ALERT_EMAIL_TO, ALERT_EMAIL_FROM, ALERT_SMTP_HOST, ALERT_SMTP_USERNAME, and ALERT_SMTP_PASSWORD; ALERT_SMTP_PORT defaults to 587 and ALERT_SMTP_USE_TLS defaults to true.
- Forward trade numbering/folder creation was absent from normal journal synchronization; the legacy backfill was not used. Canonical workbook logic now numbers only non-test row_type=trade rows, preserves all existing numbers, treats padded aliases as collisions, derives monotonic F/C sequences from workbook rows plus configured chart roots, uses open time then close time for the existing year/month hierarchy, creates folders under TRADING_JOURNAL_FOREX_ROOT/TRADING_JOURNAL_CRYPTO_ROOT, and performs deterministic allocation under the journal lock. Target Trade Number cells remain text and receive folder hyperlinks. Folder creation and workbook persistence are idempotent and atomic; failures cannot leave a workbook claiming an unlinked folder.
- The first real reconciliation validator failures were false positives caused by different openpyxl access paths materializing absent default-blank internal cells. Direct OOXML inspection proved AA1554, AA1555, AD1554, AD1555, AE1554, AE1555, AF1554, AF1555, AG1554, and AG1555 were absent and semantically empty/default before and after the targeted package patch. Presence is now considered equivalent only for a completely default blank cell with no value, formula, nondefault style, hyperlink, comment, merge significance, or other meaningful cell state. Meaningful differences still fail, and every non-target OOXML package part remains byte-protected.
- Open Bybit Demo/Live positions had no settled-funding aggregation. The service now identifies the current lifecycle from executions after the last flat state, preserves lifecycle through partial increases/reductions, distinguishes account/mode/symbol/currency/side/positionIdx, fetches paginated transaction logs in account/category batches with a short cache, applies the Bybit API sign convention (positive received, negative paid), and exposes Funding paid, Funding received, and positive-received Net funding columns. Retrieval or hedge attribution uncertainty produces a sanitized warning and an unknown dash, never a fabricated zero; order rows remain dashes.
- Crypto journal-import audit found one supported execution-history importer shared by Bybit Demo and Live; no Binance account-history importer exists. The Bybit CSV importer now reports trading fee total, funding paid, funding received, net funding, and funding cost separately. Commission is trading fees plus funding paid minus funding received. CSV Fees Paid uses positive cost/negative credit, unlike the transaction-log API. Net P/L remains gross P/L minus the combined Commission exactly once, preserving stable IDs, trailing-open deferral, legacy reconciliation, deduplication, and repeat-import idempotency. Diagnostics explicitly report that Bybit Demo/Live Commission includes funding.
- ZORAUSDT was not invalid. The metadata source remains the collection response from GET /fapi/v1/exchangeInfo, followed by exact PERPETUAL symbol selection. The prior public-request path exposed an opaque generic 502 and had no official-host transient failover. It now records only the safe endpoint, exception class, HTTP status, and Binance code/message; retries/failover occur only for connectivity, 429, and 5xx failures, never permanent 4xx failures. Filters are selected by filterType, so reordered entries work, and optional ticker/range/open-interest failures preserve partial specifications with warnings. The one post-fix live request on 2026-09-07 resolved ZORAUSDT as Binance USD-M PERPETUAL/TRADING, tick size 0.0000010, with no warnings; no regional restriction remained.
