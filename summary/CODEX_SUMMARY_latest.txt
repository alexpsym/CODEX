OANDA conversion handling:
- Corrected FX target-R conversion parsing to use the real OANDA schema:
  homeConversionFactors.lossQuoteHome.factor.
- Added support for deprecated lossQuoteHomeConversionFactor.
- Removed acceptance of fake homeConversionFactors.loss/accountLoss/account_loss paths, plHomeConversionFactors fallback, generic conversion_rate, close-row conversion, and realised-P/L inferred conversion.
- FX trades that need conversion and lack an opening-time loss factor are excluded with missing_opening_loss_conversion_factor.

OANDA history export/import:
- Updated oanda_history-clone/oanda_history.py so only opening ORDER_FILL rows export CONVERSION RATE, sourced from lossQuoteHome.factor or lossQuoteHomeConversionFactor.
- Closing fill conversion factors are left blank by the exporter and are not accepted as original opening conversion by the importer.
- OANDA CSV import now persists the opening export conversion as original_loss_conversion_factor with source/time/open transaction provenance.

OANDA API fills:
- Opening API fills now cache original_loss_conversion_factor, source, timestamp, and open transaction ID from opening OrderFillTransaction conversion factors.
- Closing API rows only reuse conversion factors from the cached opening leg, never from close fill payloads or generic context.
- Net P/L now uses realisedPL + financing - account-currency charges.
- Positive API commission and guaranteed-execution fees/premiums reduce net P/L.
- Export commission sign handling deducts positive and already-negative commission exactly once.
- Spread remains diagnostic only and is not subtracted separately.

Durable target-R metadata:
- Added a very-hidden workbook sheet named _Target R Metadata.
- Metadata is keyed by stable Row ID and stores original entry/stop/target, quantity/units, original monetary risk and currency, opening loss conversion factor, conversion source/time, and open transaction ID.
- read_master_journal_source merges this metadata back into trade rows before stats/recommendation calculations.
- update/build workbook flows refresh the hidden metadata sheet without adding visible Trade Log columns.

Recommendation coverage:
- Backend target-R payloads now include total winning trades, eligible wins, eligible FX/Crypto wins, excluded winning trades, winning exclusion reasons, and a coverage note.
- Overall recommendations are labeled when only one major asset class has eligible data.
- The refreshed workbook now shows:
  - Overall: Crypto-only eligible data - Recommended: 1.95R (current median: 2R)
  - FX: Insufficient eligible wins - recommended target unavailable
  - Crypto: Reduce target - Recommended: 1.95R (current median: 2.18R)
  - BTCUSDT: Keep target - Recommended: 1.95R (current median: 2.01R)
  - ETHUSDT: Keep target - Recommended: 1.98R (current median: 2.09R)
- STATS1 and SYMBOLS were inspected against backend calculations and matched.
- Trade Log still has no visible conversion/target recommendation metadata columns.
