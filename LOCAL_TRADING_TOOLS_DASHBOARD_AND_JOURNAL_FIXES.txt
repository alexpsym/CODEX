Current implementation evidence and root causes
- run_local_master_control.bat polls http://127.0.0.1:8000/api/startup-readiness, but after readiness it allocates an Edge debugging port/profile and calls tools\open_edge_url.bat. That helper hard-codes msedge.exe, which is why Edge opens.
- tools\windows_launchers\TradingToolsLauncher.cs runs the batch hidden and waits for its exit code. The existing builder already compiles the root Local Trading Tools.exe with Windows Forms support, making the wrapper the correct place to show a desktop-ready notification after the batch reports readiness.
- render/static/dashboard.js posts the Exit button request to /api/local-exit. render/master_service.py currently makes that endpoint call _close_local_master_edge_target(current_url) before it writes shutdown markers. Chrome has no matching Edge debug target, so the endpoint returns 409 and never starts the shutdown sequence.
- Instrument Lookup and History Export already have standalone routes at /instrument-lookup and /merged/history, but the local home template embeds both tools inline and does not include their launch buttons.
- The Journal action workspace at /dashboard/trading-journal currently owns the equity-curve DOM, Refresh Equity Curve control, and trading_journal_equity_curve.js. The local home currently places Open Orders and Positions directly above Pine Scripts.
- The main dashboard button and friendly label currently say Spreads, while the route/process identifier is spreads-clone.
- pinescripts/custom_indicator.pine declares the indicator without a declaration-level volume format. Its volume plot has format.volume, but the pane/right scale still renders raw values such as 100,000,000.000000.
- tools/master_journal_workbook.py::_recommendation_svg uses a fixed 1040 by 520 SVG and places every observation into roughly 878 horizontal pixels. The current overall-stop asset contains about 1,026 circles, so marker diameters and strokes overlap heavily. The prior padding/bounds test uses only three observations and cannot detect this real-density failure.
- In the checked-in journal\Trading Journal.xlsx, SYMBOLS!S3, T3, AA3, and AB3 contain numeric zero with General formatting, so they display 0 instead of blank. The preservation-mode resync restores source styles after generated formats and erases the intended ZERO_HIDE_FORMAT.
- P&L Calendar’s 2026 values are correctly blank because test trades are excluded, but stale direct green fills remain at cells including J2 and J9. Preservation-mode style restoration is winning over the generated profit/loss fill pass.
- YEARLY REPORT and the 2018 through 2026 sheets contain a mix of explicit horizontal="left" and horizontal=None. Excel renders many numeric/default cells right-aligned. Preservation mode deliberately restores alignment IDs, and the later semantic presentation pass does not repair horizontal alignment.
