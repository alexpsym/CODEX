PROBLEM

Commit 3fe106e correctly changed provisional recovery to chronological replay, consumed already-passed PB1 resumptions, and required genuine continuation after an oversized seed.

One candidate-to-fresh-seed handoff defect remains.

The relevant current paths are:

* ProcessImpulseSetup() accepts a normal current seed directly only when CandidateFor(candleDirection).active is false.
* When a same-direction candidate is active, the current normal seed is appended to that candidate instead.
* TryPromoteCandidate() returns false when originBar > candidate.firstBar because the newly confirmed structural origin is later than the old candidate and therefore cannot be that candidate's origin.
* TryPromoteCandidate() also abandons an expired candidate only after the current seed has already been appended to it.

This creates two seed-loss cases.

CASE A: INCOMPATIBLE NEWER ORIGIN

1. An old same-direction provisional candidate exists.
2. A genuinely newer confirmed structural origin forms after candidate.firstBar.
3. A new normal qualifying same-direction seed occurs after that newer origin.
4. CanSeedImpulse() says the current seed is eligible.
5. Direct acceptance is blocked solely because the old candidate is active.
6. The current seed is appended to the old candidate.
7. TryPromoteCandidate() rejects the old candidate because originBar > candidate.firstBar.
8. The valid fresh seed is therefore lost and the stale candidate continues blocking later seeds until expiry.

CASE B: EXPIRY ON THE CURRENT SEED BAR

1. An old provisional candidate reaches its recovery-window expiry.
2. A valid normal seed occurs on that same current bar.
3. Direct acceptance is again blocked by candidate.active.
4. The new seed is appended to the old candidate.
5. TryPromoteCandidate() then resets the expired candidate.
6. The current valid seed is deleted with it instead of being evaluated as a fresh seed.

This contradicts the independent-new-leg rule and can create another blind spot: a stale or expired provisional object must not suppress a genuinely valid new structural origin plus directional expansion.

These are code-path findings. Keep this job limited to candidate retirement and fresh-seed preservation.

REQUIRED BEHAVIOUR

1. Validate or retire old candidates before consuming the current seed

Before an active provisional candidate is allowed to absorb a current qualifying seed, determine whether that candidate is still structurally compatible and within its recovery window.

Retire the old candidate before current-seed handling when either is true:

* its recovery window has already expired before the current bar is evaluated; or
* the applicable confirmed directional origin has originBar > candidate.firstBar, proving that origin belongs to a later leg and cannot validate the old candidate.

Retirement must be symmetric for bullish and bearish candidates and must produce one concise state-change diagnostic.

2. Never lose a valid normal current seed

A current candle that satisfies normal SeedClassification() and CanSeedImpulse() must not disappear solely because an older same-direction candidate was active at the start of the bar.

On that bar, exactly one of these outcomes must occur:

* a still-compatible earlier candidate is promoted and chronologically replayed; or
* the incompatible/expired candidate is retired and the current normal seed starts the fresh parent; or
* the current normal seed is rejected for a real existing gate, with the exact reason logged.

Candidate activity alone is not a valid rejection reason.

Do not process the same current seed twice or start two parents.

3. Preserve compatible earlier-parent recovery

Do not fix this by always discarding an active candidate whenever a new normal seed appears.
