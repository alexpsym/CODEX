AUTHORITATIVE ATR DEFINITION

Use one definition across the local crypto scanner, Pepperstone EA, fixtures, labels, and documentation:

- Default ATR length: 14, configurable where the existing UI/EA convention supports inputs.
- Smoothing: Wilder/RMA, consistent with TradingView ta.atr(14) and MetaTrader iATR.
- True range for each bar: max(high - low, abs(high - previous close), abs(low - previous close)).
- Normalisation: ATR percentage = ATR / the same timeframe candle's close * 100.
- Guard zero, missing, non-finite, malformed, and insufficient-history values. They are unavailable, never 0.0000%.
- Default calculation/ranking basis: the latest fully closed candle, not the still-forming candle. Clearly state "last closed candle" in the UI. This prevents intrabar rank flicker and makes tests reproducible.
- Timeframes: 1 minute, 5 minutes, 1 hour, 1 day, 1 week, and 1 month.
- UI labels must distinguish 1m from monthly. Use 1m, 5m, 1h, 1D, 1W, and 1Mo (or an equally unambiguous existing convention). Never label monthly as another ambiguous "1M" beside 1m.
- These are ATR(14) readings on six chart timeframes. They are not simple percentage movement during only the latest minute/hour/day.
- Retrieve enough ordered history to seed and advance Wilder ATR reliably. Do not approximate ATR(14) from only the latest 14 displayed rows. Use at least 200 available candles when the source permits, while accepting newer instruments only when enough valid closed history exists.

B. Liquidity qualification

The user requires crypto to be liquid AND volatile. Implement liquidity as a hard eligibility gate, then rank eligible instruments only by ATR percentage. Never use a blended score in which extreme volatility can compensate for failed liquidity.

Use these editable starting defaults, presented as configurable screening defaults rather than a guarantee of execution quality:

- Minimum 24-hour quote turnover: 20,000,000 USDT.
- Maximum current bid/ask spread: 0.10%.
- Order-book depth band: 0.10% from the midpoint on each side.
- Minimum cumulative bid depth within that band: 25,000 USDT.
- Minimum cumulative ask depth within that band: 25,000 USDT.

Required implementation:

1. Fetch V5 tickers once for the eligible category. Use turnover24h, not base-coin volume24h, because quote turnover is comparable across USDT contracts.
2. Calculate spread percentage as (best ask - best bid) / midpoint * 100, where midpoint=(best ask+best bid)/2. Invalid, crossed, missing, or zero quotes fail liquidity.
3. Apply the turnover prefilter before order-book calls. For remaining symbols, use V5 Get Orderbook snapshots and sum price*quantity in USDT within the configured percentage band separately for bids and asks.
4. An instrument is liquidity-qualified only when every enabled threshold passes. Use AND, never OR.
5. If turnover, spread, either depth side, or snapshot freshness cannot be verified, mark liquidity Unknown/Failed and exclude it from the ranked top list by default. Never silently treat unavailable liquidity as passed.
6. Provide persisted local settings for all thresholds and a Reset to defaults action. Store them through the repository's existing safe local-state mechanism; do not commit runtime settings.
