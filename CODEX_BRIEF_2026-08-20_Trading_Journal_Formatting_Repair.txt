Required repair 2: establish one semantic formatting policy

Create or refactor a small, explicit semantic formatting policy used by STATS1 and the report sheets. It must distinguish at least:

- section/header row;
- plain count;
- percentage stored as an Excel fraction;
- R multiple;
- duration/text;
- date/timestamp;
- AUD commission;
- crypto commission with suitable optional precision;
- winner/profit fill;
- loser/loss/drawdown/commission fill;
- intentionally neutral/unfilled cell.

Requirements for that policy:

- Counts display as whole numbers (`0`), never percentages.
- Percentages display as actual percentages, normally `0.00%`, without multiplying the stored value again.
- R values display as R multiples, normally `0.000"R"`, never percentages.
- Text, duration strings, and timestamps use a neutral text/date format and no profit/loss fill unless explicitly required.
- AUD commission values use the existing currency helper and display to cents.
- Crypto commission values use the existing crypto-currency helper/logic with optional decimals sufficient to show small nonzero USDT values; do not round small values to zero or all values to whole numbers. Keep at most the existing supported eight optional decimals unless the current helper is deliberately and safely extended.
- A neutral cell must use the workbook's genuine no-fill/default fill (`PatternFill()`/equivalent), not an artificial solid-white fill.
- Generated semantic fills may be repaired, but unrelated user conditional formatting must survive.
- Formatting must be derived from the metric's semantic key/label and its section, not from the previous row's style ID or a fragile alternating-row assumption.
